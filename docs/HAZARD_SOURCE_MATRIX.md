## 0. 읽는 법

**거리** 칸은 신청유형별 임계거리다. `일반 / 다자녀 / 오피스텔·다자녀` 순서이며 `—` 는 그
유형에 Rule 이 적용되지 않는다는 뜻이다(부적격 사유가 되지 않는다).

**상태** 칸은 룰북 §6 `data_state` 다.

| 값 | 뜻 |
|---|---|
| `applied` | 판정 적용 대상. 원천이 붙으면 자동 판정한다 |
| `partial` | 일부 원천만 확보. 확인되는 건만 판정한다 |
| `missing` | 적합한 공개 원천을 못 찾았다. 판정 미적용 |
| `manual` | 원천이 없어 담당자 수기 확인 대상(LH 승인) |

**지금 상태** 칸은 그 줄이 왜 아직 안 끝났는지를 적는다. 이 칸은 읽는 사람이
이해해야 하는 것이 아니다. 항목을 검토할 때 **필요한 것이 있으면 그때 구체적으로
요청**하고, 요청 없이 끝나는 줄은 그냥 처리한다.

## 0-1. 진행 방식

한 항목을 끝내고 다음으로 넘어간다. 한 항목은 이렇게 닫는다.

| 단계 | 하는 일 |
|---|---|
| ① 기준 확인 | 판정기준이 룰북 v1.4 와 맞는지 본다. 어긋나면 룰북이 정본이다 |
| ② 원천 확인 | 실호출로 붙는지 본다. 문서 말고 응답을 믿는다 |
| ③ 필요한 것 요청 | 파일·계정·LH 확인이 필요하면 **그때 구체적으로 요청한다** |
| ④ 수정 | 실패하는 테스트를 먼저 세우고 고친다 |
| ⑤ 검증 | 실데이터로 돌려 결과를 보인다 |
| ⑥ 기록 | 그 줄의 **결정** 칸에 한 줄로 적고 다음 항목으로 넘어간다 |

## 8. 검토 순서 제안

원인이 겹치는 것부터 묶어서 보면 표를 두 번 훑지 않아도 된다.

| 순서 | 무엇을 | 왜 먼저인가 |
|---|---|---|
| 1 | **#2 · #3 공장 AND** | 파일 2종이 오면 한 번에 풀린다. 측정 정확도까지 같이 올라간다 |
| 2 | **7-1 활용신청 8종** | 신청 한 번에 7개 항목이 살아난다. 코드 수정 없음 |
| 3 | **#19~#22 건축물대장 AND** | 어댑터는 이미 있다. 배선만 하면 된다 |
| 4 | **#15 주유소 정본 교체** | 지금은 생활안전지도 근사. 산업통상부 CSV 가 정본 |
| 5 | **#4 소음 API** | 활용신청 주체만 정하면 코드 수정 없이 붙는다 |
| 6 | **#5 공장 인접** | LH 회신대로 「인접 + 정밀조사 요구」로 낮출지 확인 |

## 9. 원칙

- **한 항목씩 닫는다.** 여러 줄을 한꺼번에 바꾸지 않는다.
- **확인 안 된 조건으로 매입제외를 확정하지 않는다**(룰북 §3).
- **원천이 없는 것과 시설이 없는 것을 구분해 표기한다.** 「데이터 없음」이
  「이상 없음」으로 접히면 판정이 조용히 느슨해진다.
- 고칠 것이 있으면 **실패하는 테스트를 먼저** 세운다.

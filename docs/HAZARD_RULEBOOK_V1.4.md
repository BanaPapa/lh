## 3. 공통 판정 원칙

| 항목 | 기준 |
| --- | --- |
| 거리 | 사업지 **대지경계 ↔ 대상시설 경계**의 최단 수평거리. 중심점 거리가 아니다 |
| 경계 접촉·중첩 | `0m` |
| 임계값 동일 | 기준거리 **이내로 포함** (`measured <= threshold`) |
| 경계 미확보 | Polygon 기준 시설을 중심점 거리로 대체해 **확정판정하지 않는다** → `geometry_missing` |
| Point 예외 | 지하철·철도·**KTX** = 가장 가까운 **출구** / 대학교 = 공식 정문 (2차 생활편의성용). 정문 기준점은 **정문 > 부지경계 > 좌표 폴백** 3단(§9 참조). 철도역·KTX 역은 부지 필지 경계가 아니라 출구 기준으로 재고, 출구가 여럿이면 최근접 출구를 쓴다 (LH 2026-08-29 요청 · 출구 좌표는 박진주 대표님 수집) |
| 공개정보 | 객관적으로 식별 가능한 데이터만 자동판정. 확인 불가 조건은 추정하지 않는다 |
| 행정구역 경계 | 시·군 경계로 검색범위를 제한하지 않는다. 인접 시·군 시설도 평가거리 안이면 포함 |
| 재현성 | 동일 입력·Rule 버전·데이터 스냅샷·Geometry면 동일 결과 |
| 매칭키 | 공장 원천 간 동일시설 매칭은 **PNU 우선**. PNU 불일치·결측 시 문자열 유사매칭으로 확정하지 않는다 |
| 사업지 다필지 | 신청 필지 **전체의 합집합**을 대지경계로 쓴다 (§10) |
| 시설 다필지 | 시설이 여러 필지를 점유하면 **각 필지까지 재고 최소값**을 판정 거리로 쓴다. 담당자가 지도에서 다른 필지로 바꿀 수 있다 |

> **다필지 확정 (2026-08-28).** 정민재 이사님이 2026-08-18 에 제기한 「대표필지만 볼지, 판단시설과
> 직선거리가 가장 가까운 필지를 볼지」를 **최근접 필지**로 확정한다.
> 대표지번 하나만 보면 실제로 더 가까운 필지를 놓쳐 판정이 느슨해진다.
>
> 이때 두 가지를 구분한다.
> - **PNU 확정 단계**(데이터 제작): 시설 좌표가 여러 필지에 걸려 어느 필지의 PNU 인지 모호하면
>   확정하지 않고 검토대상으로 분리한다. 경계 공유로 우연히 둘이 잡힌 것이지 시설이 실제로
>   두 필지를 쓰는 것이 아니다. (박진주 대표님 표준 데이터셋 제작 절차 §7.2 ④)
> - **판정 단계**: 시설이 실제로 여러 필지를 점유하면 각 필지까지 재고 최소값을 쓴다.
>
> 판정에 쓴 필지와 점유 필지 전체를 결과에 실어 화면에서 확인·수정할 수 있게 한다.
> 「외 1필지」로 뭉뚱그리지 않는다 (조준환 국장님 2026-08-26 요청).
>
> **규칙과 실동작을 구분한다 (2026-08-29).** 위 최소값 규칙은 확정됐고 엔진에 다필지 분기
> (`occupied_parcels`)도 있으나, **점유 필지를 열거해주는 원천이 없어 현재 실판정은 대표 좌표가
> 포함된 단일 필지만 본다.** 원천이 「대표지번 외 N필지」의 나머지 필지를 주지 않기 때문이다.
> 「다필지 판정 적용 완료」로 읽으면 안 된다 — 규칙은 준비됐고 열거 원천 확보가 후속 과제다
> (박진주 대표님 확인 필요, §8).

## 4. 판정 상태값 (6종)

기존 5종(`not_applicable` / `exclusion_candidate` / `review_required` / `no_conflict_found` / `undetermined`)을 폐기하고 룰북 정의로 교체한다.

| 값 | 라벨 | 의미 |
| --- | --- | --- |
| `exclusion_match` | 매입제외 | 적용 Rule·데이터·Geometry가 충족되고 임계거리 이내 |
| `no_conflict_in_snapshot` | 스냅샷 내 충돌 없음 | 사용 데이터 스냅샷 범위에서 충돌 미발견. **매입 적격을 의미하지 않는다** |
| `review_required` | 검토 필요 | 후보는 있으나 Rule 조건·매칭·예외·Geometry 중 하나가 미확정 |
| `dataset_missing` | 데이터셋 미확보 | 필요 데이터셋 미확보 |
| `geometry_missing` | 경계 미확보 | 사업지 또는 시설 Geometry 미확보 |
| `not_applicable` | 미적용 | 해당 주택유형·신청유형에는 Rule 미적용 |

종합 상태는 `exclusion_match` > `review_required` > `geometry_missing` > `dataset_missing` > `no_conflict_in_snapshot` > `not_applicable` 순으로 승격한다.

## 6. 유해요소 종류 (29종)

`data_state`: `applied`(판정 적용) / `partial`(조건 확인 건만) / `missing`(원천 미확보 → `dataset_missing`) / `manual`(수기 확인)

`implementation_state`(구현/확정/검증 축 — `data_state` 와 **별개**): `ready`(판정 참여) / `not_implemented`(**미구현** — 어댑터/파이프라인 없음) / `unconfirmed`(**미확정** — LH/팀 확인 대기, 룰북 §8 병행) / `needs_verification`(**검증필요** — 엔드포인트/데이터 등록됐으나 실응답 미확인). 각 상태는 `implementation_note` 로 사유 한 줄을 함께 내보낸다. 화면은 배지 하나로 렌더한다.

- **미구현**: 없음. 2026-08-28 배선으로 건축물대장 교차확인·소음진동배출시설·factoryON 적재가 모두 붙었다.
  남은 것은 어댑터가 아니라 **외부 승인과 법령 해석**이다(§6.1 라목·§6.4 참조).
- **미확정**: 룰북 §8 `pending_items` 7건 + 카테고리 단위 미확정
- **검증필요**: `localdata` `verified=False` 데이터셋(테마파크 3종·무도학원)

`judgment_excluded`(판정 제외): 군부대·사격장. 리스트에는 보이되(판정 제외 배지) 후보 조회·거리 계산·종합상태 승격·`status_counts` 집계에 **일절 참여하지 않는다**. 상태는 `not_applicable`, 사유는 `협의에 따라 판정 제외 (원천 미확보, 2026-08-27)`.

> 원천 정합성: 종수·엔드포인트는 박진주 대표님 확정 체크리스트(`jeonbuk_checklist_260826.xlsx`, 2026-08-26)와 대조해 확정했다. 대조 감사는 `docs/DATA_SOURCE_AUDIT_260827.md` 참조. 주유소·CNG 는 API 가 아니라 CSV 원천이라 LOCALDATA 슬러그를 제거했고, 테마파크 3종·무도 2종을 분리했으며 도료류 판매소를 추가했다.

### 6.1 공장 — `RB14-FACTORY` (50m)

공장등록 = 유해공장이 **아니다**. 가~라 목의 AND 조건이 모두 확인된 공장만 판정대상이다.

| key | 라벨 | 판정조건(AND) | 원천 | data_state |
| --- | --- | --- | --- | --- |
| `factory_air_specific` | 가. 특정대기유해물질 배출공장 | 특정대기유해물질 배출 AND 공장 | 적합 공개원천 미확보 | `manual` |
| `factory_air_1_3` | 나. 대기배출 1~3종 공장 | 대기오염물질배출시설 설치 AND 1~3종 AND 공장 | 행안부 대기오염물질배출시설설치사업장 + factoryON | `applied` |
| `factory_air_4_5` | 다. 대기배출 4~5종 고시업종 공장 | 4~5종 AND 국토부 고시업종 AND 공장 | 대기배출시설 + factoryON + 국토부 고시업종목록 | `applied` |
| `factory_noise` | 라. 소음배출시설 공장 | 소음배출시설 설치 AND 공장 | 전국소음진동배출시설표준데이터 + factoryON | `applied` |
| `factory_adjacent` | 공장 인접 (정밀조사 요구) | 공장등록만 확인 (AND 미성립) | factoryON 등록공장 | `applied` |

**규칙**

> **공장은 `exclusion_match` 에 도달하지 않는다 — LH 2026-08-29 구두 지시.**
> 가~라목 어느 것도, AND 조건이 데이터로 성립하더라도 매입제외를 자동 확정하지 않는다.
> 인접이 검출되면 **`review_required` 까지만** 표시하고 **2차 생활편의성 평가 진행을 차단하지 않는다.**
> 사유(LH): 소음 50dB 기준과 공장 업종 구분을 공식 데이터로 판별할 수 없고 변수가 과다하다.
> 이 지시는 아래 나·다목의 「PNU 로 AND 성립 → `exclusion_match`」 서술(2026-08-29 낮 정정)에
> **우선한다.** AND 성립 사실 자체는 폐기하지 않고 note 에 남겨 **검토 표시를 정밀화**하는 데 쓴다
> (조준환 국장님 팀 회의자료 안건 ⑦ 방침 변경과 동일 취지).

- 가목: 원천 미확보 → 항상 `dataset_missing`, note = `별도 수기 확인 (LH 요청2 승인)`
- **factoryON 등록공장 CSV 미적재 시**: 나·다·라목과 `factory_adjacent` 는 '공장'임을
  확정할 수 없으므로 전부 `dataset_missing`, note = `factoryON 등록공장 CSV 미적재 — 적재 시 AND 판정`.
  대기배출·소음 원천만 적재됐다고 `no_conflict_in_snapshot` 을 내면 조회조차 안 한
  공장 조건을 "충돌 없음"으로 둔갑시키는 것이라 금지한다. factoryON 은 CSV 수동
  다운로드 원천(`전북/유해시설/03_06_09_factory_registry.xlsx`)이며 코드 데이터셋 키는
  `factory_registry` 다.
- 나·다·라목: AND 전 조건 성립 건만 임계거리 판정. 성립하면 `review_required`
  (LH 2026-08-29 지시 이전에는 `exclusion_match` 였다 — 위 상자 참조)
- **다목은 PNU 로 AND 가 성립해 판정에 들어온다 (2026-08-29 정정).** factoryON 원본은
  업종번호를 갖되 PNU 가 없었으나, 박진주 대표님 표준 데이터셋 제작 절차(설계서 §7.2)를
  `services/pnu_resolver.py` 로 구현해 PNU 를 확정했다. 이 절차는 **법정동코드로 PNU(19자리)를
  결정적으로 조립하고, 좌표를 연속지적도에 얹어 단일 필지일 때만 인정**한다 — 외부 조회 없이
  재현된다. factoryON 7,983건 중 7,378건 확정(92.4%), 표준본 공장은 PNU 5,582개(그중 국토부
  고시업종 공장 2,837개)를 확정했다. 따라서 다목(4~5종 AND 국토부 고시업종 AND 공장)은 PNU 로
  AND 가 성립하면 임계거리 판정에 **들어온다**.
  다만 그 결과는 `exclusion_match` 가 아니라 `review_required` 다 — LH 2026-08-29 지시(위 상자).
  AND 성립 사실은 note 에 명기해 담당자가 정밀조사 우선순위를 매길 수 있게 한다.
- 라목: 50dB 이하 또는 방음시설 예외를 데이터로 확인할 수 없으면 `review_required`
- **라목은 `exclusion_match` 에 도달할 수 없다 (2026-08-28 확정).**
  전국소음진동배출시설표준데이터 스키마에 **소음도·방음시설 필드가 아예 없다**
  (전북 146건 실측 기준 `noisVbrtMainCn` 전건 공란). 예외를 확인할 원천이 없으므로
  §3 「확인 불가 조건은 추정하지 않는다」에 따라 `review_required` 가 정상 결과다.
  **예외가 없다고 단정해 매입제외를 확정하면 오판정이다.**
  원천: `api.data.go.kr/openapi/tn_pubr_public_noise_vibration_emission_fclt_api`
  (호스트가 `api.data.go.kr` 다). 현재 403 미승인이라 전북 CSV 로만 보조 동작한다.
- **다목 AND 는 PNU 로 결정적으로 성립한다 — 종전 「주소매칭 §3 위반」 서술을 정정한다 (2026-08-29).**
  종전 룰북은 factoryON(업종번호 보유·PNU 없음)과 표준본 공장(PNU 보유·업종번호 없음)을 잇는 키가
  지번 주소뿐이라 §3(문자열 유사매칭 확정 금지) 위반이라 보았다. 그러나 설계서 §7.2 절차는
  문자열 유사매칭이 **아니다.** 법정동코드로 PNU 를 결정적으로 조립하고 좌표를 연속지적도에 얹어
  단일 필지일 때만 인정하는 절차이며, 이는 §3 이 요구하는 **PNU 우선키를 실제로 만들어내는 방법**이다.
  `pnu_resolver.py` 가 이를 구현해 factoryON·표준본 공장·소음 원천에 PNU 를 부여했으므로 세 원천은
  이제 PNU 로 AND 된다. 따라서 다목은 `dataset_missing` 이 아니라 **판정에 실제로 투입된다.**
  판정 결과값은 LH 2026-08-29 지시에 따라 `review_required` 로 상한을 둔다 — AND 성립이
  확정 근거가 되지 못할 뿐, 매칭이 성립한다는 사실 자체는 유효하며 검토 표시를 정밀화한다.
- **소음 원천도 PNU 로 공장 AND 는 성립한다(146건 중 109건 확정).** 라목이 확정에 이르지 못하는 것은
  매칭 문제가 아니라 소음도·방음시설 필드 부재(아래) 때문이다.
- `factory_adjacent`: AND가 성립하지 않은 등록공장이 50m 이내인 경우 → `review_required`,
  note = `공장 인접. 대기·소음 배출 조건은 공개데이터로 확인 불가하여 정밀조사 요구 (LH 2026-08-25 회신)`.
  **절대 `exclusion_match`로 올리지 않는다.**
- **지식산업센터 예외**: 신청 사업지와 동일 건물/동일 PNU의 지식산업센터 지원시설(소형사무실·기숙사 등)은
  건축법상 공장이 아니므로 판정대상에서 제외한다. 거리 0m로 잡히더라도 `not_applicable`,
  note = `지식산업센터 지원시설 — 건축법상 공장 아님`
- 원천 간 매칭은 PNU 우선키. PNU 불일치·결측 건은 확정하지 않고 `review_required`

  (판정규칙 담당 지침, 2026-08-28). 확정 전까지는 전부 `확인불가` 다.

## 9. 2차 생활편의성 — 정문 3단 기준 (2026-08-29 배선)

2차 생활편의성 배점 자체는 이번 변경 범위가 아니며 심사표(`/api/screening`)가 담당한다.
다만 대학교(청년 교육여건 5점) 기준점 산정 규칙만 확정·배선했다. 조준환 국장님 LOCUS §3-2 와 동일 기준이다.

- **기준점 3단**: 정문 좌표 > 부지경계 > 좌표 폴백. 위에서부터 먼저 확보된 것을 쓴다.
- **캠퍼스 통필지가 5만㎡ 이상**이면 부지경계 대신 좌표로 자동 폴백하고 그 사실을 고지한다.
  넓은 통필지는 경계 최단점이 실제 정문과 크게 어긋나기 때문이다.
- 자동 채택분은 **출처 라벨(정문/부지경계/좌표 폴백)을 결과에 명기**한다. 담당자가 정문 Point 를
  수기 지정·삭제할 수 있다.
- 엔드포인트: `GET/POST/DELETE /api/screening/front-doors`(구현: `app/screening/front_door.py`).
- **남은 리스크 (수정 중, 2026-08-29).** ① 5만㎡ 통필지 안전장치가 PNU 만으로 지정되면 임의
  대표점을 써 실제 정문이 반대편일 때 거리가 오히려 짧아질 수 있다. ② 수기 지정 대학명과 카카오
  `place_name` 이 다르면(예: 「전주대」 vs 「전주대학교」) 지정이 조용히 무시되고 좌표 폴백으로
  떨어진다. 오판정 방향은 아니나 지정이 반영되지 않는다.

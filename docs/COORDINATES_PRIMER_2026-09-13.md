# B부. 개념 교재 — 좌표계 · PNU · 지적도

## B-1. 좌표계를 두 층으로 나눠 이해하기

지구 위 한 점을 숫자로 적으려면 두 가지를 정해야 한다.

1. **데이텀(측지 기준계, datum)** — 지구를 어떤 타원체로 근사하고, 그 타원체를 실제 지구에 어떻게 붙일지(원점·방향). 예: **WGS84**, **GRS80**(한국의 Korea 2000), **Bessel 1841**(옛 동경측지계).
2. **좌표계(CRS, Coordinate Reference System)** — 그 데이텀 위에서 숫자를 어떤 형식으로 적을지.
   - **지리좌표계**: 위도·경도(도 단위). 지구 어디든 표현 가능. 단 1°의 실제 길이가 위도에 따라 달라 **거리를 바로 계산할 수 없다**.
   - **투영좌표계**: 지구를 평면에 펴서 x·y를 **미터**로 적는다. 좁은 지역에서 정확하고 거리·면적 계산이 쉽다. 지역별로 따로 정의한다.

같은 지점이라도 데이텀이 다르면 숫자가 다르다. 한국에서 Bessel(옛 지적)과 WGS84의 위경도는 **약 300~400m** 어긋난다. 옛 종이 지적도와 GPS가 안 맞던 이유다.

## B-2. WGS84 와 EPSG:4326 — 같은 것의 두 이름

- **WGS84**: GPS가 쓰는 **데이텀** 이름.
- **EPSG**: 전 세계 좌표계에 번호를 붙인 카탈로그(원래 석유 탐사 학회 EPSG 가 만듦). **EPSG:4326** = "WGS84 데이텀 위의 위경도 지리좌표계".
- 그래서 "WGS84 위경도 = EPSG:4326". 소프트웨어끼리 헷갈리지 않게 번호로 부를 뿐이다.
- **함정 — 축 순서.** EPSG:4326의 공식 정의는 (위도, 경도) 순이지만, 대부분의 API·GIS 라이브러리·WKT 는 (경도, 위도) = (x, y) 순으로 쓴다. 우리 코드의 `POINT({lng} {lat})`, pyproj 의 `always_xy=True`가 그 관행이다. **위경도가 뒤집히면 점이 인도양에 찍힌다** — 첫 번째로 의심할 버그.

## B-3. 한국에서 마주치는 좌표계 코드

| EPSG | 이름 | 데이텀 | 단위 | 어디서 만나나 |
|---|---|---|---|---|
| **4326** | WGS84 위경도 | WGS84 | 도 | 카카오·네이버 API 응답, 우리 앱 내부, VWorld 요청(`crs=EPSG:4326`) |
| **5186** | Korea 2000 / Central Belt 2010 (중부원점 TM) | GRS80 | m | **국토부 연속지적도 shp 배포 좌표계**. 박진주 delivery 의 `LSMD_CONT_LDREG_52_202608.shp`, 진용성 앱 스냅샷 |
| 5185 / 5187 / 5188 | 서부 / 동부 / 동해 원점 TM | GRS80 | m | 경도대별 평면좌표. 우리 `geo.py` 가 경도로 골라 쓴다 |
| 5179 | UTM-K | GRS80 | m | 네이버 지도 내부, 도로명주소 전자지도 |
| 5181 | 카카오 지도 내부 TM(중부원점, 가원점 500000) | GRS80 | m | 카카오 지도 타일·WTM |
| 5174 | 중부원점 TM (Bessel) | **Bessel** | m | 옛 지적도·일부 지자체 자료. **데이텀 변환 필수** |

- **GRS80 ≈ WGS84**: 타원체 차이가 수 cm 라 실무에서는 동일 취급. 5186 → 4326 변환은 "투영을 풀어 위경도로 되돌리는 것"이고 데이텀 보정은 필요 없다.
- **Bessel(5174 등) → WGS84**: 반드시 데이텀 변환(7-파라미터 또는 그리드) 필요. 안 하면 수백 m 튄다.
- TM(횡축 메르카토르)은 원점 경도(125°, 127°, 129°, 131°)에서 멀어질수록 왜곡이 커서 한국을 4개 원점으로 나눴다. 전북은 127° 중부원점(5186) 안에 있다.

## B-4. 우리 앱의 좌표 흐름 — 변환은 어디서 한 번 일어나는가

```
카카오 주소검색 ──(WGS84 lat/lng)──▶ 앱 ──(그대로, crs=EPSG:4326)──▶ VWorld 지적 API ──▶ 필지 PNU+경계(WGS84)
                                      └──(그대로)──▶ 로컬 sqlite ──▶ 필지 PNU+경계(WGS84)
                                                       ▲
                          빌드 시 1회: shp(EPSG:5186) ──pyproj 5186→4326──▶ sqlite  (cadastral_local.py `_TO_WGS84`)
```

- 실행 중 좌표계 변환은 **없다.** 카카오·VWorld·로컬 sqlite 모두 WGS84 위경도로 주고받는다.
- 유일한 변환은 **지적도 sqlite 를 만들 때**(`build_index`, 3,888,333필지, 약 30분) 5186 → 4326 으로 한 번 한 것.
- **거리 계산은 두 방식**:
  - 점↔점: 하버사인 공식(`geo.py haversine_meters`, 지구 반경 6,371km 구면 근사). 수 km 범위에서 오차 0.1% 미만.
  - 점↔폴리곤, 폴리곤↔폴리곤(대지경계↔시설경계): **위경도를 경도대에 맞는 한국 TM(5185~5188)으로 투영한 뒤 shapely 로 미터 계산**(`geo.py tm_epsg_for → _to_polygon`). 위경도 그대로 shapely 에 넣으면 "도" 단위 거리가 나와 틀리기 때문에 반드시 투영한다.

## B-5. PNU — 필지고유번호

전국의 필지(땅 한 조각) 하나를 유일하게 가리키는 **19자리 숫자**.

```
5211114100  1  1243  0003
└법정동코드┘ └┘ └본번┘ └부번┘
 (10자리)   대지=1
            산=2
```

**실제 예 — 접수 002 사업지 PNU `5211114100112430003`**
- `52` 전북특별자치도 · `111` 전주시 완산구 · `141` 효자동2가 · `00`(리 없음) → 법정동코드 `5211114100`
- `1` 대지
- `1243` 본번 · `0003` 부번 → **효자동2가 1243-3**

법정동코드 10자리 = 시도(2) + 시군구(3) + 읍면동(3) + 리(2). 이 표가 `delivery/metadata/legal_dong_codes.xlsx`이고, 우리 앱은 주소만 있을 때 이 표로 PNU 를 **직접 조립**한다(`pnu_resolver.py`, 환경변수 `LH_LEGAL_DONG_PATH`).

**PNU 가 왜 중요한가**: 주소는 표기가 제각각("효자동2가 1243-3" vs "효자동 1243-2" 충돌이 실제로 002에서 났다)이지만 PNU 는 하나다. 그래서 등록공장 대조, 협회 셋 ↔ 박진주 셋 대사, 정문 필지 지정이 모두 PNU 기준이다.

**이 프로젝트에서 실제로 난 PNU 함정**
1. **11번째 자리(대지/산)가 0** 으로 들어간 248행(박진주 0903 셋) — 지적도와 절대 매칭 안 됨. 조준환 국장이 발견.
2. **전북 시도코드 45 → 52** (2024년 전북특별자치도 출범으로 변경). 옛 자료의 `45…` PNU 는 현행 지적도(`52…`)와 안 맞는다. 강원도 42 → 51 도 마찬가지.
3. **산 번지**: "산8-15"는 11번째 자리가 2. 파서가 "산"을 놓치면 엉뚱한 대지 필지가 잡힌다.
4. **지하철 지하 주소·도로명 부속 지번**: 주소로 조립한 PNU 가 실재하지 않는 "유령 필지"일 수 있다. 그래서 우리 앱은 **좌표로 필지를 먼저 찾고** 주소 조립은 보조로만 쓴다.
5. **산업단지 로트 주소·과거 지번**: 연속지적도와 매칭이 안 되는 1~2%. 회의록도 "완전 자동화 불가, 수기 확인"으로 정리했다.

## B-6. 지적도 · 연속지적도 · 지적편집도 · 용도지역

| | 지적도 (지적공부) | **연속지적도** | **지적편집도** |
|---|---|---|---|
| 정체 | 법적 효력이 있는 **원본 공부**. 도면(도곽) 단위로 소관청이 관리 | 도곽 조각들을 **접합해 하나로 이은 GIS 데이터**. 접합 시 경계를 미세 조정 | 연속지적도 위에 **용도지역·지구 등 도시계획(토지이용규제)** 을 겹쳐 편집한 지도 |
| 법적 효력 | 있음 | **없음** — 분석·행정 참고용 | 없음 |
| 좌표계 | 과거 Bessel 도곽 좌표 등 제각각 | 전국 통일(EPSG:5186 배포) | 지도 서비스 내부 좌표계 |
| 담긴 것 | 경계·지번·지목·면적 | 경계·**PNU**·지번 (속성 최소) | 경계 + **용도지역 색**(주거·상업·공업·녹지…) |
| 제공 | 지적소관청 | 국가공간정보포털(파일), **VWorld 2D 데이터 API**(`LP_PA_CBND_BUBUN`) | 카카오/네이버 지도 「지적편집도」 레이어, **VWorld `LT_C_UQ111`(용도지역)** |
| 우리 앱 | — | 사업지·시설 경계, 정문 필지, 통필지 면적 — **전부 이것** | 회의 #5 「용도지역 병기」 = 3단계에서 붙일 것 |

한 줄 요약: **연속지적도는 "선(경계)", 지적편집도는 "선 + 색(용도)".**

용도지역(국토계획법)은 주거·상업·공업·녹지·관리·농림·자연환경보전으로 나뉘고, 그 안에서 제1종/제2종/제3종 일반주거, 준주거, 일반공업 등으로 세분된다. 회의 결정: 석유대체연료 판매업이 **주거지역**(예: 제2종일반주거지역)에 있으면 사업자등록 소재지일 가능성이 있어 25m 자동 적용 대신 「확인 요청」.

## B-7. LH 거리 측정 기준과 우리 앱의 3단 측정

- **LH 기준**: 1차 유해시설은 **대지경계 ↔ 시설 경계 최단거리**(50·25·500m). 2차 시설은 대지경계 ↔ 시설 기준점.
- 왜 "중심점 방식"은 안 되는가: 필지 중심점끼리 재면 큰 필지일수록 실제보다 멀게 나와 **임계 반전 전건이 미탐 방향**으로 쏠린다(조준환 국장이 LH 옛 웹앱을 비판한 지점). 지적도가 없어 시설이 점으로 남으면 우리 앱도 같은 문제가 생긴다("조용히 틀린 답").
- **시설 측 3단 측정**(2차, 대학·종합병원):
  1. 정문 **필지경계**(수기 지정 PNU) — 통필지(면적 임계 이상)면 검증된 정문 좌표가 있어야 확정
  2. 정문 **좌표**(수기 지정 좌표 또는 네이버 「{시설명} 정문」)
  3. 시설 **좌표**(대표점) 폴백 + 「정문 미확인」 고지
- **역**은 가장 가까운 출구 좌표. 문·출구가 여럿이면 후보를 모두 싣고 최근접이 기본, 담당자가 선택(2a `front_door_candidates`).
- **여유구간(BOUNDARY_BUFFER_M=100)**: 기준거리 초과 100m 까지는 「검토」 표시. **예비검색 슬랙(SEARCH_SLACK_M=150)** 은 별개 — 시설 폴리곤이 커서 점 거리는 멀어도 경계 거리는 가까운 시설을 후보에서 놓치지 않기 위해 경계 부착 대상을 넉넉히 잡는 값. 조준환 엔진이 둘을 묶었다가 5건을 놓친 실측이 있다.

## B-10. 자습 과제 (직접 손으로 해 보면 개념이 붙는다)

1. `backend/.venv` 파이썬에서:
   ```python
   from pyproj import Transformer
   t = Transformer.from_crs("EPSG:4326", "EPSG:5186", always_xy=True)
   print(t.transform(127.1040299284, 35.8152174903236))   # 002 사업지 → 중부원점 TM (m)
   ```
   나온 x, y 가 대략 (209xxx, 4xxxxx) 범위인지 보고, `always_xy=False` 로 바꾸면 무엇이 달라지는지 확인.

4. `tools/lh_baseline/run_five_sites.py` 를 돌려 041·105 의 결과 JSON 에서 `measurement_tier`·`geometry_source`·`distance_m` 을 찾아 본다.
5. 다른 LLM에게 물어볼 질문 예시: "EPSG:5186과 5181의 차이는?", "하버사인과 Vincenty 의 오차 차이는 전북 규모에서 의미가 있나?", "R-Tree 가 bbox 조회를 어떻게 빠르게 하나?", "PNU 로 필지를 찾을 수 없는 경우는 언제이고 어떻게 폴백해야 하나?"

## B-11. 용어집

| 용어 | 뜻 |
|---|---|
| 데이텀(datum) | 지구 타원체 + 원점·방향. WGS84·GRS80·Bessel |
| CRS / SRS | 좌표참조계. 데이텀 + 좌표 표기 방식 |
| EPSG 코드 | CRS 카탈로그 번호. 4326=WGS84 위경도, 5186=한국 중부원점 TM |
| TM(횡축 메르카토르) | 한국 평면좌표계의 투영법. 원점 경도별로 서부·중부·동부·동해 |
| 투영(projection) | 위경도 → 평면 m 좌표. 역투영은 반대 |
| 하버사인 | 구면 위 두 점 거리 공식. 점↔점 근사에 사용 |
| 필지 | 지적공부에 등록된 땅 한 구획. 지번 하나 |
| PNU | 필지고유번호 19자리 = 법정동코드10 + 대지/산1 + 본번4 + 부번4 |
| 법정동코드 | 시도2+시군구3+읍면동3+리2 (10자리). 행정동코드와 다르다 |
| 지적도 | 법적 효력 있는 원본 필지 도면 |
| 연속지적도 | 지적도를 접합한 GIS 데이터(참고용, EPSG:5186 배포) |
| 지적편집도 | 연속지적도 + 용도지역 등 도시계획 정보 |
| 용도지역 | 국토계획법상 토지 용도 구분(주거·상업·공업·녹지…) |
| 통필지 | 대학 캠퍼스처럼 매우 큰 한 필지. 대표점으로 재면 왜곡 |
| 정문 기준점 | 대형 시설 거리 측정의 기준(LH 확정 2026-09-11) |
| 여유구간 | 기준거리 초과 100m 까지 「검토」 표시 |
| R-Tree | 공간 인덱스. bbox 로 후보를 1~2ms 에 좁힌다 |
| shapefile(.shp/.dbf/.shx/.prj/.cpg) | GIS 벡터 파일 묶음. .prj 가 좌표계, .cpg 가 문자 인코딩(연속지적도는 EUC-KR) |
| VWorld | 국토부 공간정보 오픈플랫폼. 지적·용도지역·건물 등 2D 데이터 API |
| 인허가 원장(LOCALDATA) | 행안부 지방행정인허가 데이터. 주유소·숙박·위락 등 시설 좌표·영업상태 |
| factoryON | 한국산업단지공단 등록공장 시스템. 등록공장 원장(PNU 보유) |

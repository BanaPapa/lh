# LH 기존 모델 대조 기준선

LH 가 자체 제작해 운용하던 웹앱 2종의 판정 로직을 그대로 옮긴 재현본과,
같은 사업지를 이 앱으로 돌려 대조하는 도구다.

**왜 필요한가.** 이 앱은 납품본이 아니라 교차검증 도구다. "우리 판정이 LH 기준과
같은가"를 규칙이나 원천이 바뀔 때마다 다시 물어야 하는데, 재현본이 없으면
그 질문에 답할 수 없다.

---

## 구성

| 파일 | 역할 |
|---|---|
| `lh_replica.py` | LH 웹앱 2종의 판정 로직 재현본. **숫자를 바꾸지 않는다** |
| `lh_scores.py` | 재현본을 신청 원장 전건에 적용해 기준선 생성 → `data/lh_118.json` |
| `run_ours.py` | 같은 사업지를 이 앱으로 전수 판정 → `data/ours_118d.json` |
| `compare.py` | 두 결과를 대조하고 차이 원인을 분류 |
| `data/lh_118.json` | LH 기준선 (2026-08-27 산출) |
| `data/ours_118d.json` | 본 엔진 결과 (2026-08-27 산출) |

## 재현본이 옮긴 것

`03_ 1단계 유해시설 공간분석 모델` 에서:

- `haversineMeters()` — 지구반경 6,371,000m 구면 직선거리
- `getThresholds()` — 숙박·위락·위험시설 25m 제외 / 50m 주의, 혐오시설 500m 제외 / 1,000m 주의
- `analyzeSites()` — 최악 등급 채택, 동점이면 더 가까운 시설로 교체

`04_ 2단계 생활입지평가 모델` 에서:

- `hav()` — km 단위 구면거리
- `calcScores()` — **일반형(15·15·10) 하드코딩**. 청년·고령자형 계산 경로가 없다
- `buildDB()` — 파일 하나만 올려 쓰는 구조라 사업지 소재 시군 마스터만 적용된다

> LH 모델은 신청유형 개념이 없어 숙박·위락을 전 건에 적용한다. 대조 범위를 가장
> 넓게 잡기 위해 `run_ours.py` 는 위락·숙박이 모두 적용되는 `house/multi_child` 로 돌린다.

## 실행

LH 원본 자료는 저장소에 담지 않는다 (신청 원장에 개인정보가 섞여 있다).
폴더 위치를 환경변수로 지정한다.

```bash
cd backend
export LH_SOURCE_DIR="/c/Users/<사용자>/Documents/카카오톡 받은 파일/LH 용역/결과물/AI공모전"

# ① LH 기준선 산출 (수 초)
PYTHONPATH=. ./.venv/Scripts/python.exe -m tools.lh_baseline.lh_scores

# ② 본 엔진 전수 판정 (실 API 호출 · 30분 안팎)
PYTHONPATH=. ./.venv/Scripts/python.exe -m tools.lh_baseline.run_ours

# ③ 대조
PYTHONPATH=. ./.venv/Scripts/python.exe -m tools.lh_baseline.compare
```

`LH_SOURCE_DIR` 에 있어야 하는 파일:

```
01_ 매입약정 신청자 전체파일(260430).xlsx
02_ 1단계_ 유해시설(전북 전체)_260715.xlsx
00_ 전북 시군별 좌표(260415)/시설_DB마스터_{전주,군산,익산,정읍,김제,남원,완주}.xlsx
```

②는 카카오·브이월드·오피넷·TAGO 를 실호출하므로 `backend/.env` 키가 필요하다.
①·③만 돌리면 동봉된 `data/*.json` 으로 대조 결과를 바로 볼 수 있다.

## 주의

1. **`lh_replica.py` 의 숫자를 고치지 않는다.** 대조의 기준선이므로 "고쳐서" 옮기면 대조가 성립하지 않는다. LH 모델의 결함(25/50m 일괄 적용, 점 기준 거리, 일반형 하드코딩)도 그대로 둔다.
2. 결과 JSON 은 산출 시점의 스냅샷이다. 원천이 갱신되면 ②를 다시 돌려야 한다.
3. `data/ours_*.json` 은 실행 시점의 공개 API 응답에 의존하므로 완전한 재현은 되지 않는다. 큰 폭의 차이가 나면 원천 변동을 먼저 의심한다.
